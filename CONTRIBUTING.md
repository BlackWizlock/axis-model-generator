# Участие в проекте

Изменения принимаются через pull request (PR). В описании укажите проблему,
поведение до и после изменения, проверочные команды с результатами и
сохраняющиеся ограничения. Обновите [CHANGELOG.md](CHANGELOG.md) в разделе
`[Unreleased]`. Не объявляйте поддержку платформ, генерацию моделей или
нормативную готовность без проверяемых результатов.

## Самостоятельная работа

Нужны Python 3.14 или новее и Git для экспорта. Внешних зависимостей времени
исполнения у текущего Python-ядра нет. Из каталога исходников:

```sh
PYTHONPATH=src python3 -m unittest discover -s tests -v
PYTHONPATH=src python3 -m model_generator example.zip --output report.json
PYTHONPATH=src python3 -m model_generator example-package.zip --kind package --output package-report.json
python3 scripts/export-public.py --revision HEAD --output _output/source-snapshot
```

Входные `example.zip` и `example-package.zip` нужно подготовить отдельно.
Синтетические образцы создаются в `tests/fixtures/`; реальные клиентские
файлы не нужны для включённых тестов. Экспорт выполняется после фиксации
проверенных файлов в Git, в ещё не занятый каталог результата.

В PowerShell сначала задайте `$env:PYTHONPATH="src"`, затем используйте
`python -m model_generator` или `python -m unittest discover -s tests -v`.
Windows и реальные сценарии Windows/Revit пока не проверены.

## Изменения и проверки

1. Выберите одну атомарную задачу с явными входами, результатом и файлами.
2. Для изменения поведения добавьте проверку, которая сначала обнаруживает
   проблему. Используйте синтетические данные и конкретные ожидания.
3. Выполните подходящие проверки и полный набор тестов перед передачей
   на ревью. Проверьте запуск в автономном экспортированном снимке.
4. Для новых публичных файлов добавьте точные пары `source` и `export`
   в `public/export-allowlist.json`; широкие шаблоны включения не используйте.
5. В PR приложите команды и результаты, обновление журнала и ограничения.

При разработке с агентами применяется subagent-driven development (SDD):
отдельный исполнитель получает одну атомарную задачу, после неё независимый
ревьюер проверяет соответствие требованиям и качество. Замечания исправляются
и проверки повторяются до перехода к следующей задаче. Исполнитель учитывает
чужие изменения и фиксирует только свои файлы.

## Данные и лицензия

В Git и PR включайте только синтетические образцы. Не добавляйте клиентские
модели, результаты их обработки, личные сведения, `.env`, ключи и конфигурацию
окружения. Снимок исходников не должен содержать прежнюю приватную историю.
Результаты экспорта и диагностические отчёты храните вне Git.

Собственный код и документация находятся под [Apache-2.0](LICENSE).
Сохраняйте [NOTICE](NOTICE). Включая сторонний код, укажите его происхождение
и лицензию и проверьте совместимость. Blender, runtime и будущий код с bpy
сохраняют отдельную лицензионную область; Apache-2.0 проекта их автоматически
не перелицензирует.

Об уязвимостях сообщайте по [SECURITY.md](SECURITY.md). Публичные обсуждения
и PR не используйте для раскрытия уязвимости или передачи чувствительных данных.
